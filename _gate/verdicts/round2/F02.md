# F02 — A session boundary is a transition, not a failure — round 2, zero-context skeptic

**Verdict: PASS.**

### 1. Claim, stated back
If an agent writes its resolved conclusions to an append-only store outside the session, the next
session can rebuild a working boot from a single generated file cheaply enough that hitting the end
of a session is routine rather than a loss — and the rebuild is judged by whether the new session
*makes* the moves its stored decisions imply, not by whether it can recite them.

Claim stated, and stated narrower than its own title. The finding explicitly separates "the
falsifiable part" from "the slogan," and imports F01's behavioural criterion so that "rebuilt"
is not self-graded. Pass step 1.

### 2. Evidence line
There is a measurement, and it is a comparison against a named alternative rather than a quote of
intent: the 2026-04-26 three-session trial, conclusion-store versus flat-markdown, same 175KB
source, same small model, with a table — 57 KB vs 176 KB substrate, 631 vs ~80,000 units of
session-1 ingest, session-3 reconstruction successful vs failed.

Pass step 2, and the reason it passes cleanly is the honesty apparatus attached to the number:
- the units are declared uninterpretable ("the trial did not record whether one unit is a token, a
  line or a record") and explicitly fenced off from the token counts elsewhere in the report;
- the session-3 "win" is decomposed rather than banked — it was a ten-minute wall-clock timeout, a
  property of the harness, and the text says so and then says the markdown agent "might simply have
  been slow and correct";
- n=1, one source, one model, no repeat run, no published harness, unequal tuning, and the accuracy
  column is named as a judgement not a score. The finding claims only "the direction and the order
  of magnitude, not the constant."

The design statement ("Sessions are ephemeral. The OS is not.") *is* a quote of intent — and the
text labels it as such in the same breath: "a witnessed note, not a measurement." Correctly filed.

### 3. Mechanism rebuilt in five lines, from the text alone

```
1 act        -> append(session_log.jsonl, line)                       # live, lossless
2 close      -> summary = fold(session_log) into ONE conclusion entry # compress to conclusions
3 persist    -> append(identity_db.jsonl, summary + decisions + insights)  # never delete
4 boot       -> pick(last 3 summaries) + active(decisions) + insights # active = unsuperseded
5 emit       -> ONE boot file; next session reads it and resumes
```

Reproducible. The one term that would otherwise stall a rebuild — "active decision" — is defined in
place: unsuperseded, computed by walking the store and dropping every entry some later entry points
at. Correction-by-append with a back-pointer is stated, so the store is implementable without
guessing. Pass step 3.

Gap that does not fail the step: the *content* of the fold in step 2 (what makes something a
conclusion versus narrative) is defined by example — decision-with-rationale, insight,
session-summary — not by a rule an implementer could apply mechanically. Anyone rebuilding this
will write a different summarizer and get different numbers. Worth knowing; not disqualifying,
because the finding's claim is about the shape of the loop, not the quality of the fold.

### 4. NOTE — one way it could be wrong that the text does not address
The text pre-empts most of the obvious attacks: the naive-comparator objection ("a competent
retrieval index over the same markdown might close much of the gap"), the unwritten-conclusion loss,
the wall-clock artifact, and — sharply, against itself — the recency-window objection that "all
identity is there" degrades to "all *recent* identity is there" after a few hundred sessions, with
the observation that a three-session trial sits below the horizon where that would show.

What it does not address: **the trial measured ingest cost, and the claim is about continuity.**
A store can be cheap to boot from and still carry the wrong things. Nothing in the record shows a
session that *failed* because a needed conclusion was never written — the store is only ever
evaluated on what it did carry, never audited against what the session actually needed. Absent a
recall-failure ledger (conclusions later discovered missing), "the boundary is cheap" is measured
and "the boundary is not a loss" is assumed. The finding names the unwritten-direction loss as
unmeasured, which is close, but it frames it as an acceptable known cost rather than as the
thing that would falsify the headline.

Second, smaller: step 3 says "never deletes," and the archive therefore grows without bound while
step 4 reads a fixed window — so the append-only property protects an archive that, by
construction, nothing routinely reads. The finding gets to the edge of this and stops.

### 5. Terms used before defined
No fatal case. `atom`, `bank`, `wrap`, `ingest`, `recall --warm`, `remember` all appear in the
Mechanism section, and each is glossed inline at first use in this file ("distills its lessons into
atoms, one stored lesson per file"; "plants them in the bank (the atom store on disk, outside the
session)"), with AP3 pointed at in the header. "Conclusion" is defined before it is leaned on, which
is the one that mattered. "Checkpoint" appears late, undefined and not in AP3, but its meaning is
carried by the surrounding sentence ("force a checkpoint and a state write before the boundary
arrives"). Minor.

### The one sentence to change
None required for a PASS. If one is taken, it is the claim sentence
"an agent that persists resolved conclusions to an external append-only store can rebuild a working
boot at the next boot from a single generated file, at an ingest cost small enough that the rebuild
is routine" — the evidence establishes the *cost* clause and not the *working* clause, and the
sentence should say which half the trial measured.
