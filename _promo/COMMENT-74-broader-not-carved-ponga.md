Broader, not carved out. After that 2026-09-23 run the rule became: the cheap seat may sort tracker rows and gather evidence pointers, but it may not close any row. Every "satisfied" is re-derived by a second seat that reads the row's verb (fold, redesign, assure, verify) and tests the evidence directly, file by file and commit by commit.

We did not carve out the failing claim type because the seven misses were not one type. They asked for three different things (a fold of existing stores, a design, an assurance outcome); what they shared was the judge's reading, where the named tools existing on disk was taken as the work being done. The three that held were the mechanically checkable ones: a frontmatter field present, a commit recording a choice, a folder of six reports.

The hole: we have not run the judge again under a carve-out, so I cannot tell you whether "close only mechanically checkable rows" would have held its precision. That is one run of ten, not a measured rate.
