# F01 — Identity does not transfer by injection — round 2, zero-context skeptic

**Verdict: PASS.**

### 1. Claim, stated back
Handing a model its identity documents at boot makes it able to *restate* those values while
leaving its actual reasoning unchanged — the finding claims this as one witnessed uncontrolled
instance plus a named controlled test that was not run, with a corollary that a cross-machine
identity handover does not fit in ~10k tokens.

Claim stated. Pass step 1. The finding does the unusual and correct thing of pre-declaring the
scope of what it is asserting ("The record holds one uncontrolled instance of this, not the
controlled run"), so the strong general claim is explicitly declined and is not judged here.

### 2. Evidence line
Present and it is a witnessed use, not intent:
- the behaviour is dated and counted — "booted with all 13 CVs in context and ran hollow for 11
  messages" — a number attached to a specific incident, not a plan;
- the repair carries a magnitude — ~29,000 tokens of cold re-anchoring;
- the 10k ceiling is explicitly labelled *arithmetic, not measurement*, and the arithmetic is
  shown line by line. Labelling a derived number as derived is the opposite of assertion-as-evidence.
- the hidden-harness-cache observation is a witnessed configuration fact (empty cache on the new
  machine), independent of anyone's judgement about texture.

Pass step 2. Note that the load-bearing word "hollow" *is* a judgement rather than a metric — but
the finding says so itself in its own limitations section rather than letting it pass as data, and
the countervailing 2026-04 observation (injection *did* change a subagent's output) is kept in
place instead of dropped. Evidence that argues against the claim and survives in the text is the
strongest signal in this file.

### 3. Mechanism rebuilt in five lines, from the text alone

```
peeks  = recall_warm(intent)            # spines only: title + preview, free, no scoring write
chosen = agent_selects(peeks)           # the selection is the witnessed act
bodies = remember(chosen)               # sole path to full text; records take-up, earns weight
boot   = pose_questions(bodies)         # seeds + questions; never the string "you are X"
ok     = judge_behaviour(next_session)  # scored on moves made, never on recitation
```

Reproducible from the text plus AP3. The glossary supplies spine, body, take-up, weight, recall,
remember; the finding supplies the ordering and the rule that the fetch is what earns. Pass step 3.

Two things the text leaves under-specified but which do not break the rebuild: how `agent_selects`
chooses (any selector works for the mechanism's logic), and what `judge_behaviour` scores against
(the Claim section supplies it — value-implied moves, blind-scored). Both are implementable.

### 4. NOTE — one way it could be wrong that the text does not address
The text does address prompt position, attention decay, missing cache, and mid-session correction —
an unusually complete list. What it does not address: **the witnessed door may be doing its work
through cost, not through witnessing.** `remember` forces the full body into context; `recall`
does not. Every reported success involves more text actually present, and every reported failure
involves less. If so, the epistemology of "the choice is the signal" is decorative and a plain rule
— "always load the bodies" — reproduces the entire effect with no scoring, no take-up, no door. The
record contains no arm where a body was loaded *without* being chosen, which is the only arm that
separates the two.

Second, smaller: the claim is stated about "a model", but the single incident is one model on one
day. F01 concedes model-vintage drift, but not the possibility that the effect is specific to a
model family's instruction-following style rather than to injection as such.

### 5. Terms used before defined
None fatal. The finding points at AP3 in its header, and — notably — it also glosses inline the
terms a stranger would trip on at the moment they appear: *harness* ("the program that runs the
model as an agent"), *atom* ("one stored lesson, one file"), *body*, *weight* ("never touches the
model's parameters"), *estate* ("the whole set of projects that share one bank"), *CV-013* ("core
value number 13 of the thirteen the agent boots with"). `spine` appears only inside the pseudocode
comment and is defined in AP3. `ingest` and `wrap` are used in the Mechanism section before any
gloss, but both are named with their function in the same sentence. Acceptable.

### The one sentence to change
None required for a PASS. If one improvement is taken, make it the Mechanism's line
`bodies  = remember(chosen, depth=body) # the only read path; earns weight by being taken` —
it should say what distinguishes the earning door from simply loading more text, since as written
the reader cannot tell whether the mechanism's power comes from the witnessing or from the volume.
