# Skeptic verdict — F06 recall-is-foveated-demote-dont-delete

**Reviewer:** zero-context skeptic. Read only: README.md, _gate/SKEPTIC-BRIEF.md, findings/F06.
Archive and ledger not consulted; the finding was judged standing alone.

## Verdict: FAIL — step 3, mechanism not reproducible

Steps 1 and 2 pass. Step 3 fails on a specific, repairable gap.

### Step 1 — claim stated back: PASS
Recall ranks every stored record against the current intent and admits only the top band into
context; a record that stops paying off loses weight, falls under a computed threshold and leaves the
default view without being deleted; one successful witnessed read brings it back with no extra verb.

### Step 2 — evidence line: PASS
Witnessed uses and numbers, not statements of intent. The load-bearing lines are the measured pair
`stored=75.00, recomputed=72.19` on a 1073-record copy of the live bank; the 7497-record histogram
(7353 near neutral / 112 at 75 / 1 near 85) that sites the threshold at 80; the dry run naming 97
records; and the wake test at 79 recomputing to 90.6. The retraction is stronger evidence than the
claim: it reproduces the bug to a literal repeated value, `112.5083001343761` at two timestamps a
year apart. I re-derived that cancellation from the stated formula alone and got the same behaviour
(112.5 at both t=100 and t=465 days for a fixed history) — the formula as written does cancel common
aging, so the retraction is honest and self-checking.

### Step 3 — five-line rebuild: FAIL

```
score(rec, now)  = 100 + SUM(d.delta * exp(-LAMBDA[rec.type] * (now - d.at))) / SUM(exp(-LAMBDA[rec.type] * (now - d.at)))
recall(intent)   = for r in store: s=sim(r,intent); emit top-N where score(r,now) >= 80, log impression(r, hash(intent)); band s by 0.45 / 0.18
remember(slug)   = r = store[slug]; r.history.append(delta=+POS, at=now); return r.body      # only door that returns a body
dormant(r)       = score(r, now) < 80                                                        # computed at query time, never written
wrap()           = for r in losers_of_same_query_set: r.history.append(delta=-min(3, losses/10), at=now) unless floor(score)<85 or r.type in {feedback, owner}
```

The skeleton rebuilds, but two constants the mechanism cannot run without are absent from the text,
so the rebuild is a guess at exactly the points the claim rests on:

1. **The magnitude of a `remember` delta (`+POS`) is never given.** Section Mechanism ¶2 says only
   that a fetch "appends a positive delta". Because ¶3's formula is a *weighted mean*, not a sum, the
   effect of one read is entirely determined by how many prior deltas it is averaged against — a
   quantity the text also never gives. I cannot reproduce the headline wake result. Starting from a
   dormant 79, the recomputed 90.6 requires the new delta to dominate the mean; on a two-entry
   history I get 92.0 for a +5 delta and 94.5 for +10, i.e. the number is reachable but only by
   choosing both the delta size and the history depth myself. The single most important number in
   the finding — the one proving dormancy is reversible without a special verb — is not derivable
   from the finding.
2. **`wrap`'s "floored at 85" contradicts the threshold at 80** as stated. If the demotion pass
   cannot take a record below 85, and dormant is `score < 80`, then that pass can never make a
   record dormant. Combined with the retraction (idle time never moves a score), no described path
   reaches dormancy except an explicit human dispute — which is precisely what the dry run shows
   (all 97 were disputed). The text presents the floor as a safety rail without noting that it
   closes the only remaining automatic route to the state the finding is about.

### Exact sentence that needs to change
> `remember <slug>` is the only door returning a record's full body, and each fetch appends a
> positive delta to its history.

This sentence must carry the delta's magnitude, and the read-time formula's denominator must state
the history depth used in the 79 → 90.6 wake test — without both, step 3 cannot be completed from
the text. (I have not rewritten it; the wording is the author's to fix.)

### Step 4 — one way it could be wrong that the text does not address: NOTE
The finding's own "What it could still be wrong about" already concedes there is no A/B against plain
recency and that the constants were reasoned from a histogram. The gap it does *not* address is
**impression logging as a self-reinforcing ranking loop.** Demotion is charged to records that "kept
losing to a sibling in the same query set" — but a record can only lose an impression it was shown
in, and it is only shown if it already scores above 80 and ranks near the top. A record that drifts
just under threshold stops accruing impressions entirely, so it stops being eligible for either the
negative signal or the positive one. Its score then freezes at whatever value hid it. "Waking is the
same read path running again" holds only for an operator who already knows the slug and calls
`remember` directly; for anyone arriving through `recall`, the periphery is not dormant-but-active,
it is unreachable-by-default. That is the same worry the text quotes from a later review — *"a hidden
atom that can never be reached is a deletion by another name"* — but the text treats it as an
untested edge case, when the impression-eligibility loop makes it the expected steady state. The
finding claims falsifiability on two conditions; the second one ("dormancy must be reversible with no
special verb") is met only under a reading of "verb" that excludes prior knowledge of the slug.

### Step 5 — terms used before they are defined
- **"warmth BANK" / "bank"** — quoted in Where it came from, used as the store's name in Evidence
  ("a copy of the live bank"), never defined. A reader cannot tell if it is the database, an index,
  or a cache.
- **"atom"** — appears only inside quotations ("a weak atom is reported", "the hidden atom") while
  the finding's own prose says "record". Never stated that they are the same thing.
- **"witnessed" / "the witnessed door"** — load-bearing in both the wake test and the lukewarm
  incident, and it is what separates an earning read from "a plain file read earns nothing".
  Inferable as "a read through `remember`" but never said.
- **"disclaimed" / "disputed"** — the 75 floor is "the disclaim floor" and the 97 dry-run records are
  "explicitly disputed". Two words, apparently one state, neither defined; this matters because the
  dry run's whole weight rests on what that state is.
- **"impression"** — introduced mid-sentence in Mechanism ¶1 as the logging of a shown record. Used
  in the abstract earlier ("the substrate logs impressions") before it is given meaning.
- **"organ"** / **"sleep organ"** — used in Evidence and in the lukewarm incident as though known.
- **"temperature"** vs **"score"** — two separate 0-1 and 0-100 scales run through the finding
  (0.45/0.18 bands vs 80/85 thresholds) and are never distinguished; a reader will try to reconcile
  them and cannot.
- **`wrap`** — named as the pass that charges demotions, never explained as a session-close event.
- **`kappa`** — the proposed fix constant, given no value or selection rule.

### Note on the retraction
Keeping the retraction in the finding is the right call and it is the most credible section here: it
reproduces rather than asserts, and it invalidates the finding's own headline mechanism for a
six-week window. But it is not fully propagated. The Claim section still says a record "that stops
paying off loses weight and drops out", and Mechanism ¶3 still presents the cancelling formula as
current, with the correction deferred to the end as "a recommendation, not a merge". A reader who
stops at the Mechanism section leaves with a claim the same document later withdraws.
