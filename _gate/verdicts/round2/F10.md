# Round-2 zero-context skeptic verdict — F10 (a generator validating itself shares its blind spot)

Reviewer: zero-context skeptic, no prior review read. Sources read: README.md, _gate/SKEPTIC-BRIEF.md,
appendix/AP3-glossary.md, findings/F10-a-generator-validating-itself-shares-its-blind-spot.md.

**Verdict: PASS** (with two NOTEs; no failing step).

## Step 1 — state the claim back
A model checking its own output carries into the check the same assumption that produced the defect,
so an artifact must be judged by a seat that did not produce it — except at the node that selects
which lessons to keep, where the run's own seat is required because the material judged is the run's
own experience, and separation alone is not sufficient: what closes a gap is a test tier the producer
could not pre-read.

Stated in one sentence. Step 1 passes.

## Step 2 — the evidence line
Witnessed, not asserted, in three independent places:
- April 2026 incident report, quoted at spine level, with a ground-truth search result: the cited
  value "ZERO matches in entire codebase" — a negative search, i.e. a witnessed check, not an opinion.
- August 2026 bootstrap: a real type defect (string paths vs path objects) caught on round one by a
  seat that had not read the generated body; round two 16/16, second component 9/9, pre-existing suite
  441 then 457 green, and the text notes the suite predates the generated code so it cannot share the
  blind spot.
- 2026-08-28 counterweight: a builder in a separate scratch directory read the blind test net anyway
  and cited the other seat's test ids verbatim. This is a measurement that cuts *against* the
  finding's own first version, and the finding carries it.

The one quotation that is only an expectation — the plan sentence about low-tier models tending to
role-play — is explicitly labelled as such in the text ("an expectation, not a measurement"; "'tend
to' carries no rate behind it"), and the finding names what would settle it. Correctly demoted rather
than smuggled. Step 2 passes.

## Step 3 — rebuild the mechanism in five lines
From the text alone:

```
1  producers = {seat(r) for r in receipts_consumed_by(node)}
2  if seat(gate) in producers: refuse(E04)          # artifact nodes only
3  if node is lesson_selection: require seat(gate) == seat(run)   # inverted rule
4  for r in claimed_receipts: rerun(r.command, r.branch); assert outcome == r.outcome
5  post_speech: if claim_says("wrote file"|timing|status) and tool_calls == []: label(simulated)
```

Everything needed is in the text: `receipts_consumed_by` is defined (reads the logged tool-call and
test-run records the node took as input), `seats(...)` is defined, `rerun_every_claimed_receipt()` is
defined including what agreement means (same pass/fail outcome, same branch) and what disqualifies a
receipt (named command not found or not runnable). Step 3 passes.

Reproducibility gap that is *not* fatal but worth recording: the text never says who assigns a seat
id, nor how "the same branch the producer worked on" is recovered if the producer's branch has moved.
A reimplementer can build the check; they would have to invent the identity scheme.

## Step 4 — one way the claim could be wrong that the text does not address (NOTE)
The text already anticipates the strongest rival (incentive-structural vs epistemic) and says the
arm was never run — that is unusually honest. The rival it does *not* address: **the independent seat
may be doing better simply because it re-executes, not because it is independent.** In the August
case the counter-tests were both blind *and* newly executed; in the 441/457 suite the discriminating
property named is age, not seat. A same-seat check that re-ran every receipt might find the same
defects, which would make `assert seat(gate) not in producers` (line 2) decorative and
`rerun_every_claimed_receipt()` (line 4) the whole mechanism. The finding's own retraction ("structure
helps and does not close it; what closes a gap is a tier the producer cannot pre-read") points
straight at this and stops one step short of naming re-execution as the possible sole active
ingredient.

Second, smaller NOTE: the falsification test as written ("if self-checks and independent checks find
the same defects at the same rate, the claim is wrong") is never run anywhere in the file. The claim
is declared falsifiable in a specific way, and then all evidence offered is of a different kind. The
"What it could still be wrong about" section concedes this ("Nobody ran the same task through a
self-check and an independent check under matched conditions and counted"), so it is disclosed, not
hidden — but a reader may notice that the stated falsifier and the presented evidence do not meet.

## Step 5 — terms used before defined
No failures. The finding opens with a pointer to AP3 and, in addition, inlines definitions for the
two load-bearing terms at first use: *seat* ("one model context launched separately from the others,
holding only what its own brief gives it") and *receipt* ("a logged record of a tool call or test run,
carrying ids and enough detail to be run again"). *atom* is glossed in place ("single stored lessons").
*wrap* is glossed in place ("the ritual that closes a session"). `remember` is used with its door
sense explained. AP3 covers seat, receipt, atom, gate, wrap, remember, recall, bank.

Two terms pass only on charity, and are recorded here rather than as a failure:
- **"spine level"** ("a document frozen at spine level") — AP3 defines *spine* as an atom's short free
  surface, title line plus preview. Applied to an incident report the phrase is doing different work
  and a stranger must guess it means "only the summary survives, not the body".
- **"tier"** in "the sabotage tiers" / "a test tier the producer could not pre-read" — AP3 defines
  *tier* as a model-trust ranking (T1/T2/T3/OS_TIER/MOD_TIER). Here it means a class of test. Same
  word, unrelated sense, and the glossary entry actively misleads on this one.
- **"E04"** is used as a bare error code with no referent. It reads as an internal id; harmless, but
  it is the one token in the file a stranger cannot resolve from any file in this release.

## The one sentence to change
> The verdicts that actually found bugs came from the interaction probe and the sabotage tiers, which
> cannot be pre-read.

This sentence carries the finding's post-retraction position — that pre-readability, not seat
separation, is what does the work — and it is the only place two undefined terms ("interaction probe",
"sabotage tiers") land at once, in the same clause, at the moment the reader most needs to know what
they are. A stranger cannot tell whether a "sabotage tier" is a kind of test, a stage of review, or a
model rank (the glossary pushes them toward the last, which is wrong). Everything else in the file is
either defined inline or reachable from AP3.

Not a FAIL: the claim survives without the reader resolving those two names. But this is the sentence
to change.
