# Verdict — F02 "A session boundary is a transition, not a failure"

Reviewer: zero-context skeptic (never seen ECHELON). Read: README.md, _gate/SKEPTIC-BRIEF.md, F02.
**VERDICT: FAIL — step 5 (undefined term, and the file is truncated mid-sentence on exactly the term that carries every number).** Steps 1-4 pass; step 3 passes more cleanly than in F01.

## Step 1 — claim restated (PASS)
If an agent writes its *resolved* conclusions (decisions, insights, session summaries) to an append-only store outside the session, then ending a session costs only a cheap, routine rebuild from one generated boot file rather than a loss of state — so a session boundary is a scheduled transition, not a data-loss event to be mitigated by better in-session compression.

The finding narrows its own slogan to the falsifiable part in its second sentence, and states the counter-claim it is beating (in-session compaction) plus that counter-claim's failed prediction (re-injecting a summary does not recover window budget). This is the cleaner claim statement of the two findings.

## Step 2 — evidence line (PASS)
There is a measurement, not just a design statement, and the finding explicitly separates the two: the 2026-03-25 note is labelled "a witnessed note, not a measurement," and the 2026-04-26 three-session comparison is given as the measurement — same 175KB / ~100k-token source, same small model:

| | conclusion store | flat markdown |
|---|---|---|
| substrate footprint | 57 KB | 176 KB |
| session-1 ingest | 631 units | ~80,000 units |
| session-3 reconstruction | successful (~28k units) | FAILED (timeout) |

Crucially the finding disarms its own headline: "The 126x number is an ingest-cost ratio, not an accuracy result," the accuracy column is "a judgement, not a score," and "what the trial supports is the direction and the order of magnitude, not the constant." That is the correct claim for n=1 and it clears "evidence is assertion."

Residual objection that does not fail the step: the session-3 task was *word-for-word reconstruction of the source*, which is the one task a conclusion store should be worst at and a transcript-holding agent best at — yet the transcript agent lost by timing out. The reported win is therefore a win on **wall-clock limits**, not on fidelity. A ten-minute session limit is a property of the harness, not of the architecture; on a harness with no limit the markdown agent might simply have been slow and correct.

## Step 3 — five-line rebuild (PASS)
Rebuilt from the text alone, no outside knowledge needed:

```
1. on each significant action:  append(session_log.jsonl, event)                 # live, lossless
2. on session close:            s = summarize(session_log) -> ONE summary entry
3. append(identity_db.jsonl, s + decisions + insights)                           # append-only; supersede, never delete
4. on next boot:                sel = last_3(summaries) + active(decisions) + insights
5. write(boot_file, sel); the new session reads boot_file and resumes            # cost flat as store grows
```

Everything needed is on the page: both files are named, the selection rule is concrete ("last 3 summaries + active decisions + insights"), the correction discipline is stated (append a superseding entry), and the flat-cost property follows from step 4 being a fixed-size selection. Unlike F01, no step rests on an undefined effect. A stranger could build this.

Two soft spots that do not fail the step: `active(decisions)` is undefined (what retires a decision?), and `summarize` carries the entire compression yet is given only as "compresses to conclusions, not to prose."

## Step 4 — one way it could be wrong that the text does not address (NOTE)
The finding names the loss of unresolved material and the retrieval-index confound. It does not address **the append-only store's growth as a selection problem in disguise**. Step 4's cost is flat only because it takes the *last 3* summaries and *active* decisions. After a few hundred sessions the boot file is no longer "all identity is there" — it is a recency window over an archive, and "zero reconstruction needed" quietly becomes "zero reconstruction of the recent past." The 2026-03-25 note's own diagnosis of markdown compaction — after about five sessions the reconstructed identity is "a faint echo of the original" — applies to any fixed-window selector, including this one; being append-only protects the *archive*, not the *boot*. The trial ran three sessions, below the horizon where this would show. Nothing in the evidence distinguishes "the boundary is cheap" from "the boundary is cheap for three sessions."

Second: the two mechanisms are not exclusive. An agent can persist conclusions externally *and* compact in-session; the finding refutes an opponent who only compacts.
